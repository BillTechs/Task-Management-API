# Task Manager API + Streamlit

A modular FastAPI task manager backed by SQLite, with automated tests and a Streamlit web UI.

## Features

- Create, list, retrieve, partially update, and delete tasks.
- Filter by `status` and/or `priority`.
- Pydantic input validation and clear 404 errors for missing tasks.
- Parameterized SQL queries and SQLite constraints.
- Automated endpoint tests using an isolated temporary database.
- Streamlit interface for listing, filtering, creating, editing, and deleting tasks.

## Run locally (macOS/Linux)

Use Python 3.11 or 3.12 for broad package compatibility.

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
pip install -r requirements.txt
```

### 1. Start the API

From the project root:

```bash
uvicorn app.main:app --reload
```

- Swagger UI: http://127.0.0.1:8000/docs
- Health check: http://127.0.0.1:8000/

The `tasks.db` file and table are created when the API starts.

### 2. Start Streamlit

Open a second terminal in the same project directory, activate the same virtual environment, then run:

```bash
streamlit run streamlit_app.py
```

Open the local URL Streamlit prints (usually http://localhost:8501). By default, the UI calls `http://127.0.0.1:8000`. Set `API_URL` when the backend is hosted elsewhere.

### 3. Run tests

From the project root:

```bash
pytest -v
```

Tests use a temporary SQLite database and do not intentionally modify your local `tasks.db`.

## API reference

Task fields:

| Field | Type | Allowed values / constraints |
|---|---|---|
| `id` | integer | Generated by SQLite |
| `title` | string | Required, 1–100 characters, not blank |
| `description` | string | Optional, max 1000 characters |
| `priority` | string | `low`, `medium`, `high` |
| `status` | string | `pending`, `in_progress`, `completed` |
| `created_at` | string | Generated by SQLite |

| Method | Endpoint | Purpose |
|---|---|---|
| `POST` | `/tasks` | Create a task |
| `GET` | `/tasks` | List tasks |
| `GET` | `/tasks/{task_id}` | Retrieve one task |
| `PATCH` | `/tasks/{task_id}` | Update supplied fields |
| `DELETE` | `/tasks/{task_id}` | Delete a task |
| `GET` | `/tasks?status=pending` | Filter by status |
| `GET` | `/tasks?priority=high` | Filter by priority |
| `GET` | `/tasks?status=pending&priority=high` | Combine filters |

### Example request

```bash
curl -X POST http://127.0.0.1:8000/tasks \
  -H 'Content-Type: application/json' \
  -d '{"title":"Learn FastAPI","description":"Build a CRUD API","priority":"high","status":"pending"}'
```

### Example partial update

```bash
curl -X PATCH http://127.0.0.1:8000/tasks/1 \
  -H 'Content-Type: application/json' \
  -d '{"status":"completed"}'
```

Invalid request data returns `422`; missing task IDs return `404`; an empty update returns `400`.

## Deployment

### Deploy API to Render

1. Push this repository to GitHub.
2. In Render, create a **Blueprint** and select the repository containing `render.yaml`.
3. Confirm the service and persistent disk settings, then deploy.
4. Copy the deployed API URL and verify `<your-api-url>/docs`.

The included Render configuration mounts a persistent disk at `/var/data` and stores SQLite at `/var/data/tasks.db`. Confirm that the disk is available on your selected Render plan; without persistent storage, local SQLite data may be lost on redeploy/restart. A single SQLite file is appropriate for a small demo, not high-write multi-instance production traffic.

### Deploy Streamlit UI to Streamlit Community Cloud

1. Open Streamlit Community Cloud and deploy this GitHub repository.
2. Set the app file path to `streamlit_app.py`.
3. In app settings/secrets, set an environment variable named `API_URL` to your deployed Render API URL, for example `https://your-service.onrender.com`.
4. Redeploy/reboot the Streamlit app and test create/list/update/delete.

The Streamlit service must use the public API URL, not `127.0.0.1`, because localhost on Streamlit Cloud refers to the Streamlit container itself.
